# printerctl - Autonomous Development Guide

## Project Overview

`printerctl` is a command-line application written in C that communicates with 3D printers running Marlin Firmware through an USB serial connection.

Its primary objective is to transmit G-code generated by PrusaSlicer in a reliable, observable and fault-tolerant manner while keeping the architecture modular and maintainable.

The project is intended to be developed mostly autonomously by AI agents under controlled engineering practices.

# Safety Policy

Safety has priority over convenience.

## Home

The printer currently should **not perform homing during development**, because endstop sensors are not available or should not be relied upon.

Therefore:

* G28 must remain disabled by default.
* Executing `home` requires explicit confirmation.

Example:

```bash
printerctl home --i-understand-no-endstops
```

---

## Emergency Stop

M112 is reserved for emergencies only.

Never send automatically.

---

## Automatic Commands

The software must never automatically:

* home axes
* heat the printer
* move axes
* extrude filament

unless explicitly requested by the user.

# Serial Communication

Implementation requirements:

* configurable port
* configurable baud rate
* configurable timeout
* line-based communication
* wait for `ok`
* detect:

  * Error
  * busy
  * echo
  * Resend

Support future checksum implementation.

Never flood the serial buffer.

---

# G-code Streaming

Implementation should:

* validate file
* ignore comments
* stream line-by-line
* wait for acknowledgement
* log every transmission
* detect timeout
* stop gracefully on failure

# APCUPSD Integration

The host computer is protected by a UPS.

The printer is NOT connected to the UPS.

Therefore APCUPSD integration is informational only.

When a power event occurs:

Power failure:

* record timestamp
* record current file
* record last acknowledged line
* record estimated progress
* record printer state
* mark session as interrupted

Power restored:

* record event
* notify operator

The software must never automatically resume a print after power restoration.

Configuration:

```ini
[apcupsd]
enabled=true
on_powerfail=record
on_online=record
auto_resume=false
```

# Coding Guidelines

* Modular design.
* No global mutable state unless justified.
* Defensive programming.
* Explicit error handling.
* No silent failures.
* Keep functions small.
* Prefer composition over monolithic modules.
* Compile warning-free with:

```bash
-Wall -Wextra -Wpedantic
```
