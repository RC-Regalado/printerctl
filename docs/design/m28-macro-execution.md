# M28 Design — Built-in Macro Execution

## Scope

M28 implements the first physically executable built-in macros through the
M27 typed macro domain.

It does not add PLP `MACRO_*` messages, CLI macro UX, user-defined macro
files, queues, jobs or event subscriptions.

The internal execution path is:

```text
control/runtime command
→ worker
→ built-in registry resolution
→ complete macro validation
→ ownership/state validation
→ typed MOVE executor
→ printer/Marlin terminal response
```

## Executor ownership

The worker is the only owner of mutable physical execution.

```text
PRINT active → macro execute = BUSY → zero macro serial writes
MACRO active → PRINT_START = BUSY → zero print-start serial writes
```

The control/socket context never executes macro steps directly. It only sends
internal runtime commands and consumes runtime events.

## Typed MOVE translation

Supported physical step types:

- `MOVE_RELATIVE`
- `MOVE_ABSOLUTE`

There is no `RAW_GCODE`, script, shell, loop, condition, variable or nested
macro step.

Translation is generated by the worker from validated typed fields:

```text
MOVE_RELATIVE
→ G91
→ G1 <selected axes> F<feedrate>

MOVE_ABSOLUTE
→ G90
→ G1 <selected axes> F<feedrate>
```

Every move uses an explicit validated feedrate. The executor never inherits
the firmware modal feedrate.

## Coordinate-mode policy

Macro movement is deterministic and does not depend on the previous firmware
`G90`/`G91` state.

Successful macro completion authorizes a final `G90`, leaving a known absolute
coordinate-mode postcondition.

If a macro fails before that final `G90` can be safely authorized, M28 does not
send `G90` as automatic cleanup. The modal state must be treated as unknown by
operators and future UX.

## Geometry configuration

M28 adds optional daemon-owned calibration geometry keys:

```text
calibration.min_x
calibration.max_x
calibration.min_y
calibration.max_y
calibration.safe_z
calibration.xy_feedrate
calibration.z_feedrate
```

They follow the existing configuration precedence:

```text
built-in defaults
→ config file
→ CLI overrides
```

The keys are optional. Missing calibration geometry does not prevent
`printerctld` from serving unrelated functionality.

Validation before execution:

- finite numeric values;
- `min_x < max_x`;
- `min_y < max_y`;
- `safe_z > 0`;
- `xy_feedrate > 0`;
- `z_feedrate > 0`.

No machine-bound safety claim is made because authoritative machine dimensions
are not part of the current architecture.

## Built-in semantics

`maintenance-z-lift` requires:

```text
calibration.safe_z
calibration.z_feedrate
```

Steps:

```text
MOVE_RELATIVE Z +safe_z Fz_feedrate
```

The five calibration macros require full calibration geometry:

```text
front-left  = min_x, min_y
front-right = max_x, min_y
center      = midpoint(min_x,max_x), midpoint(min_y,max_y)
back-left   = min_x, max_y
back-right  = max_x, max_y
```

Each calibration macro executes:

```text
1. MOVE_RELATIVE Z +safe_z
2. MOVE_ABSOLUTE X/Y target
3. MOVE_RELATIVE Z -safe_z
```

They do not use absolute `Z=0` and do not home automatically. Absolute XY
movement assumes the operator has already established valid coordinates; M28
does not invent a synthetic homed-state flag.

`park` remains registry metadata only.

## Validation and failure semantics

Before the first physical command:

```text
lookup
→ resolve config-backed values
→ validate full macro definition
→ validate execution ownership/state
→ commit execution
```

Macro execution is sequential and non-transactional.

If step `N` fails:

```text
steps < N may already have physical effects
steps > N are not newly authorized
```

There is no automatic rollback, lowering move, home, retry, recovery or resume.

## Cancellation readiness

The executor checks control commands before each newly authorized physical
macro command.

Cancellation means:

```text
stop authorizing future macro physical commands
```

M28 does not add user-visible macro cancellation. It does not send `M112`,
`M410` or cleanup movement.

## Observability

Macro execution reuses the runtime event/snapshot direction:

```text
worker event
→ event_pipe
→ control snapshot
```

The snapshot includes:

- `execution.kind = MACRO`;
- macro id;
- execution state;
- current step;
- total steps;
- terminal result.

Macro observability must not gate execution. The control context remains the
single event-pipe consumer, preserving the PRINT-LIVE-001 remediation model.

## Remediation amendments (2026-10-14)

Added after `docs/audit/m28-review.md`; see `docs/audit/m28-remediation.md`.

- **Units.** Every macro first sends `G21` and requires its terminal response
  before any `G90`/`G91` or motion. A `G21` failure stops the macro with zero
  further TX. Postcondition: success leaves `G21` + `G90`; failure or
  cancellation after `G21` leaves millimetres and an unknown coordinate mode.
- **Representability.** All commands are formatted before the serial port is
  opened. Rejected (INVALID_ARGUMENT, zero TX): |coordinate| > 9999.999 mm,
  non-zero |coordinate| < 0.001, feedrate outside [0.001, 99999.999] mm/min,
  any line longer than 95 bytes. `-0.0` is sent as `0.000`. These are wire
  limits for Marlin (MAX_CMD_SIZE 96, 32-bit float), not machine travel limits.
- **Cancellation.** The macro control poll runs before each TX and during each
  ACK wait (every received line and every poll slice). It consumes the
  async-signal-safe SIGTERM/SIGPWR flags, PRINT_CANCEL_POWER_FAILURE and
  SHUTDOWN. Once cancellation is committed no further command is sent and no
  cleanup G-code is generated; continuous `busy:` chatter cannot delay it.
  Power-failure cancellation reports CANCELLED with failure_reason
  SHUTTING_DOWN. PRINT_CANCEL does not target macros.

## Safety

M28 adds no path for clients to submit arbitrary G-code.

Physical macro commands are generated only from daemon-owned built-in
definitions that pass complete typed validation. Invalid macro id, invalid
configuration, missing geometry or active print state all fail before macro
serial writes.

M28 introduces no automatic:

- home;
- movement outside the selected built-in macro;
- heating;
- extrusion;
- `M112`;
- `M410`;
- recovery;
- resume;
- rollback movement.
